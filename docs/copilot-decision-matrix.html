The rule that decides most of it

Own it → index it. Licence it → call it.

A Graph connector makes a persistent copy in a Microsoft-hosted index and grants it to Entra groups. Against your own content that is cheap, broad and correct. Against Moody's or S&P it collides with redistribution, per-seat entitlement, derived-data and AI-use clauses simultaneously — so licensed content is fetched live, entitled by the vendor, attributed and timestamped, and never stored.

      Delivery paths — how the data gets there

      The layer your original matrix doesn't cover, and the one where the money and the licensing risk actually sit. These are not alternatives to the surfaces above; every surface consumes one or more of them.

      Read the columns carefully — only some of them are alternatives to each other. Three axes are in play, and a column is mutually exclusive only with its own neighbours on the same one:

      • How the data reaches the model: pre-indexed retrieval (gallery or custom connector), a semantic model, or live invocation. This is the real fork, and it is what Figure 1 turns on. A semantic model is a third answer rather than a flavour of the other two: it holds a copy like an index does, but computes per user and enforces row-level security at query time like a live call does.
      • Which custom connector, once you have chosen to index: agent-hosted or direct push. Not a preference — your deletion SLA and your hosting decide it. Only the agent deletes, and only the push runs without a Windows host.
      • How a live tool is exposed, once you have chosen invocation: an API action, an MCP server you build, or a ready-made MCP server somebody else publishes. Same job; different wire protocol, different client reach, and in the third case somebody else’s code between Copilot and your data.
      • Where the whole thing runs: M365 surfaces, or an application you host. Foundry sits on this axis, not the other two — inside it you would still choose retrieval versus invocation, with your own index and your own tools. It is here because “the askers are not M365 users” is a real branch, not because it is a peer of a connector.

      What the columns genuinely share, and what the cost rows are really measuring, is reach per unit of build: a connector is picked up by every M365 surface with nothing told to it, an API action is wired to each agent by hand, an MCP server is wired per client over a shared protocol, and a semantic model reaches whoever already opens Power BI.

      A catalogue is not an analytics workload, and this is where people go wrong. Descriptive metadata — which table holds what, who owns it, what it is tagged with, what feeds it — is a search problem over names and descriptions, so it belongs in the index however structured it looks. A semantic model earns its place when the answer is a number computed across rows, or when row-level security has to be enforced per user. Those are different questions about the same warehouse, and they take different routes.

      The split that matters most

      Data you own vs data you licence

      Same technology, opposite answers — and the deciding factor is contractual, not technical. Get the licence read before the architecture is drawn, because it changes the design rather than the paperwork.

      First-party — you own it

      Index it, and index it broadly

      • No redistribution question. It's yours; a second copy in your own tenant index costs you nothing contractual.
      • No per-query meter. Crawl cost is compute you already pay for. Widening the audience is free.
      • M365-wide reach for one build. One connector puts the content in Copilot chat, Word, Outlook, Teams and Search without a retrieval story per surface.
      • The second source is cheap. Once the engine exists, a new SQL source is a class and a config file — weeks becomes days.

      But not always. Row-level security, MNPI, restricted lists and dynamic information barriers are all first-party and all wrong for an index — a Graph ACL is written at push time, and a wall-crossing next Tuesday isn't in it. Those go through a live call like vendor data does.

      Third-party — you licence it

      Call it live, and never store it

      • Redistribution. A searchable corpus serving users is usually storage and redistribution, not internal use. It needs an explicit rider.
      • Entitlement counting. Index it, ACL it to a group, and you have entitled everyone in that group. Pay for 200 seats, expose 3,000, and that is exactly what an audit finds.
      • AI and derived-data clauses. Recent agreements address ingestion into AI systems explicitly. Several vendors now sell an AI-use tier — ask what it costs before designing around it.
      • Caching windows and attribution. Many agreements cap retention and require source and as-of timestamp. Last Tuesday's index entry satisfies neither.

      The trap: the LLM decides how many calls to make. "Compare our exposure across these fifteen counterparties" is fifteen vendor lookups per turn, per user. Model volume at 5–10× human usage, budget per user per day in the action itself, and log call volume from day one.

      The hybrid that resolves all three cases

      Index the metadata. Call for the value.

      Index that you hold a rating for an issuer, its as-of date, the methodology, your own analyst commentary, and a link — all of which is either yours or non-substantive. Then fetch the rating itself live, entitled and attributed. Copilot answers "which issuers did we downgrade internally last quarter, and what does Moody's say now?" — first half from the index, second from the call. Neither half alone gets there, and the licensed content never lands in the index. The same shape resolved your Power BI semantic model and your Fabric warehouse.

      In practice

      Three questions, in order

      1. Where is the person standing when they ask? Teams, Word or Outlook → an M365 surface, grounded by a connector. Your public site or a call-centre desktop → Foundry or Copilot Studio; M365 Copilot is not reachable from there. An IDE or an analyst's tooling → MCP.

      2. Is the answer content, or is it computed? Text that can sit still — a ticket, a case note, a policy, a measure's definition — index it. A number that moves, or anything that writes — call it. Indexing a computed value freezes it, and a frozen number that disagrees with the live report is a control problem, not a nuisance.

      3. Who enforces access, and can they still do it afterwards? If the answer is "the source system, live, per user", you cannot index it without losing the enforcement. That single question resolves RLS, MNPI, information barriers and vendor seat licensing in one move.
