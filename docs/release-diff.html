An adversarial pass over this diff caught a defect shipped in v1.2.22. PushTiming's header and its mostly-in-flight verdict still described Kiota's RetryHandler as sitting inside PutAsync, and closed by advising the operator to “re-run with RetryHandlerOption.MaxRetry = 0” to settle whether the run was throttled.

GraphPipeline does exactly that, in the same release. So v1.2.22 told an operator to perform a fix already in the build, and withheld a conclusion the build had earned. ADD src/PushCore/PushTiming.cs +415 New fixed-memory timing subsystem: TimingSeries is a lock-free quarter-octave histogram (48 octaves x 4 sub-buckets, 192 counters, ~1.5 KB regardless of run size) with interlocked count/sum/nonZero, a compare-and-swap max, and percentiles interpolated inside the containing bucket; PushTiming holds one series each for source read, prepare, write in flight, write backoff, commit, row total and content bytes.
